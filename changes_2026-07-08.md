# Changes — 2026-07-08

## Feature: Reuse an existing database on setup (never override)

When the setup wizard connects to a database that already contains a Pixel
installation, it now **reuses that database and preserves its data** instead of
treating it as a fresh install. Schema upgrades (additive migrations) still run,
so an older database is brought up to date without any data loss.

### Detection rule
An "existing installation" is defined as: **the `users` table exists and holds
at least one row.** This is checked when the user runs *Test Connection* on the
Database step, and re-verified server-side at completion time (the completion
check is the source of truth).

### Behaviour when an existing database is detected
- The schema bootstrap (`setupDatabase()`) runs as before — it was already fully
  idempotent (`CREATE TABLE IF NOT EXISTS` + additive column migrations), so it
  never drops or overwrites tables/records.
- **No new admin account is created.** The user signs in with their existing
  credentials.
- The wizard **skips the Admin Account step** entirely and shows an "Existing
  database detected" notice on the Database step and again on the Review step.

### Behaviour for a fresh database (unchanged)
- All tables are created and the admin account from the wizard is required and
  created, exactly as before.

## Files changed

### `app/api/setup/test-db/route.ts`
- After the existing `CREATE DATABASE IF NOT EXISTS` (a no-op for an existing
  database — never destructive), the endpoint now checks whether a `users`
  table exists with ≥1 row and returns `existingDatabase: boolean` in the JSON
  response.

### `app/api/setup/complete/route.ts`
- Removed the unconditional up-front requirement for admin fields.
- After `setupDatabase()` runs, the route counts rows in `users`:
  - **Users already exist** → admin creation is skipped entirely.
  - **No users** → admin fields are required (returns `400` with a rollback of
    `site.config.json` to the incomplete state if missing) and the admin account
    is created as before.
- Response now includes `existingDatabase: boolean`.
- Added comments clarifying that `setupDatabase()` is non-destructive.

### `app/(setup)/setup/page.tsx`
- Added `existingDb` state to the wizard.
- `StepIndicator` now takes a dynamic `steps` list and renders positional
  numbers, so the sequence stays `1..n` when the Admin step is hidden.
- `StepDatabase` reports detection via a new `onDetect` callback and shows an
  "Existing database detected" info banner after a successful test. Detection is
  reset whenever a connection field is edited.
- The Admin Account step is filtered out of the indicator and skipped in
  navigation (`Application → Review`, and `Review` back → `Application`) when an
  existing database is detected.
- `StepReview` hides the Admin Account summary in favour of an info notice and
  omits the `admin` payload from the completion request when reusing an existing
  database.

## Feature: Bulk upload assets from CSV (Settings → Reference Data)

Added a new **Bulk Upload Assets** tile under Settings → Reference Data that
lets users import many assets at once from a CSV file.

### Format
- **CSV only.** First row is a header row naming the columns.
- **Required columns:** `name`, `department`.
- **Optional columns:** `short_code`, `description`, `type`, `category`,
  `lifecycle_status`, `business_owner`, `technical_owner`, `domain`, `vendor`,
  `tier`, `strategy`, `notes`, `app_url`.
- Column headers are matched case-insensitively (spaces/dashes → underscores).
  Unknown columns are ignored.

### Behaviour
- A `department` that does not already exist is **auto-created** (as
  `Unpublished`) and linked; the results report lists every department created.
- Multiple departments per asset are supported by separating names with `;`
  or `|`.
- Lookup columns (`domain`, `vendor`, `tier`, `strategy`) are matched to
  existing records **by name**; unmatched values are left blank and surfaced as
  a per-row warning.
- `type` defaults to `Other`, `lifecycle_status` to `Proposed`, `category` to
  `Application` when omitted; an unrecognised value falls back to the default
  with a warning.
- Every created asset and every auto-created department is written to
  `audit_log` (`CREATE`).

### Files added
- **`app/api/assets/bulk/route.ts`** — `POST /api/assets/bulk`. Accepts
  `{ rows, userId, userName }`, preloads lookup tables into name→id maps,
  resolves/auto-creates departments, applies defaults, inserts each asset +
  department links, audits, and returns a `{ summary, results }` report with
  per-row status and warnings.
- **`app/(dashboard)/settings/bulk-upload-assets/page.tsx`** — client page with
  an inline format description, a CSV-only file picker, a client-side CSV parser
  (handles quoted fields/commas/newlines), a validated preview table, and a
  post-import results table (created/failed counts, auto-created departments,
  per-row notes).

### Files changed
- **`app/(dashboard)/settings/page.tsx`** — added the "Bulk Upload Assets" tile
  (Upload icon) to the Reference Data section, linking to the new page.

### Verification
- `npx tsc --noEmit`: no new type errors in any added/changed file.

## Feature: Business Services (service catalogue composed of assets)

Added a new top-level **Business Services** area — a customer-facing service
(e.g. "Telephony for Retail") composed of the assets that deliver it (Telstra,
Twilio, Kraken, AWS…), each with a role. Designed to be consumed by other
platforms via a stable, slug-addressable read API.

### Model (per agreed design)
- **Flat membership + role.** A service links to many assets; each membership
  carries a role of `Core`, `Supporting`, or `Dependency`, plus optional notes.
- Services **reuse** existing reference data: a criticality `tier` (FK→tiers),
  a `domain` (FK→domains), and business/technical owner fields.
- Each service has a **stable `slug`** (e.g. `telephony-retail`) that external
  systems reference instead of the internal UUID. Auto-generated from the name,
  editable, unique (collisions get `-2`, `-3`, …). Renames do **not** change the
  slug unless a new one is explicitly supplied.
- Status: `Planned` / `Active` / `Degraded` / `Retired`.

### External consumption
- No authentication was added or changed (existing platform/gateway API-key
  mechanism sits in front, per instruction).
- `GET /api/services/[id]` and `GET /api/services/by-slug/[slug]` return a
  **composed view** — the service plus its member assets (name, type, vendor
  icon, lifecycle, role, notes) and `updatedAt` for caching.

### Schema (added to idempotent `setupDatabase()` in `lib/db.ts`)
- `services` — id, name, `slug` (UNIQUE), description, status ENUM, `tier_id`,
  `domain_id`, business/technical owner, created_by + timestamps.
- `service_assets` — junction (PK service_id+asset_id), `role` ENUM, notes.

### Files added
- **`lib/slug.ts`** — `slugify()` + `uniqueSlug()` (collision-safe, exclude-self
  on update).
- **`lib/services.ts`** — `getComposedService(db, {id|slug})` shared by the id
  and slug read routes.
- **`app/api/services/route.ts`** — `GET` (list + asset count), `POST` (create,
  auto-slug).
- **`app/api/services/[id]/route.ts`** — `GET` (composed view), `PUT`
  (slug-stable), `DELETE` (cascades service_assets). Audited.
- **`app/api/services/[id]/assets/route.ts`** — `GET` members, `POST` add
  (validates role, 409 on duplicate).
- **`app/api/services/[id]/assets/[assetId]/route.ts`** — `PATCH` (role/notes),
  `DELETE` (remove member).
- **`app/api/services/by-slug/[slug]/route.ts`** — slug-addressable composed
  view for external platforms.
- **`components/services/ServiceFlow.tsx`** — ReactFlow diagram: service hub →
  member assets, edges/badges coloured by role (mirrors the Projects flow).
- **`app/(dashboard)/services/page.tsx`** — Service Catalogue list + create/edit
  modal (name, auto-slug, description, status, tier, domain, owners).
- **`app/(dashboard)/services/[id]/page.tsx`** — service detail: hero, List/Flow
  toggle, composition grouped by role, add/edit/remove members.

### Files changed
- **`types/index.ts`** — added `ServiceStatus`, `ServiceRole`, `Service`,
  `ServiceAsset`.
- **`lib/db.ts`** — added `services` + `service_assets` table creation.
- **`config/navigation.ts`** — new **Business Services** group (Service
  Catalogue, Layers icon) placed above the Assets group.
